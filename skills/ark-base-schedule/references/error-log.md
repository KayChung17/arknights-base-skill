# 常见错误记录

## 布局定义

错误：将 243 写成 3 个贸易站、4 个制造站、2 个发电站。

修正：243 为 2 个贸易站、4 个制造站、3 个发电站；342 为 3 个贸易站、4 个制造站、2 个发电站。

## 混合目标

错误：在班次层面声明一个产品，导致所有制造站生产同一产品。

修正：每个制造站单独保存 `product_id`，校验器检查混合目标是否同时包含两类产品。

## 精英等级

错误：同名技能总是取最高精英版本。

修正：只选择用户实际精英等级已经解锁的最高版本。

## 全局计数

错误：将当前房间干员作为整个基建干员范围。

修正：计算器接收独立的 `global_operators`，校验时使用当前班次全部房间干员。

## 替换机制

错误：把巫恋“低语”当成固定 65% 效率，或只替换贸易站直接效率层。

修正：巫恋按其他工作干员人数获得每人 45%，清零其他干员提供的订单效率，同时保留进驻基础效率、站外控制中枢加成、特殊订单和心情效果。冬时替换制造站直接生产力层，设施与全局联动保持独立。

## 单位

错误：将龙舌兰的 `+500 龙门币` 当成固定每单收益，或与 `+X%` 直接相加。

修正：龙舌兰只对原始 4 赤金且非违约的订单加价，逐订单模型按订单概率结算期望收益。

## 排班复用

错误：生成器主动复用干员，校验器无条件判错。

修正：排班文件声明跨班复用策略，校验器按 `forbidden` 或 `allowed_with_warning` 处理。

## 0.5.0 回归项

- 修正“每天上线三次”等同于三个 8 小时班的建模错误。
- 修正 342 攻略设施等级被统一当成三级站的问题。
- 修正把跨区间零复用当成主要质量指标的问题。
- 修正技能数据库未覆盖时仍可发布 final 方案的问题。
- 修正只按房间填满人员、没有攻略体系基线的问题。
- 修正没有核对赤金、订单、碎片、经验、材料和龙门币闭环的问题。
- 修正全局计数只看到当前遍历到的部分房间的问题。

## 0.6.0 回归项

- 修正只在单一攻略模板附近搜索的问题，攻略改为比较候选。
- 修正单房间高分组合全部依赖同一核心干员、导致全局模型无可行解的问题；组合库加入多样性尾部。
- 修正 MILP 目标未考虑区间仓库封顶的问题。
- 修正 `simulate_schedule.py` 无法直接读取求解结果中嵌套 assignments 的问题。
- 修正办公室等未被旧效率计算器支持的设施导致组合枚举崩溃的问题。
- 修正 TSV/CSV 之外无法直接读取 XLSX 练度表的问题。
- 明确 MILP 代理目标、候选库完整性和最终复算最优性属于三个不同层面。
