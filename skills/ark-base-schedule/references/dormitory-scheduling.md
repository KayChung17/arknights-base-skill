# 宿舍与重复日心情建模

## 采用的游戏机制

- 宿舍基础恢复率：`1.5 + 0.1 * 宿舍等级 + 0.0004 * 氛围值`。
- 1 至 5 级宿舍的满氛围基础恢复率依次为 `2、2.5、3、3.5、4` 每小时。
- 工作站基础心情消耗为 1 每小时。
- 贸易站与制造站进驻 2 名非红脸干员时减耗 0.05，进驻 3 名时减耗 0.1。
- 控制中枢每名非红脸干员提供全局减耗 0.05，上限 0.25。
- 每间宿舍最多容纳 5 人；休息人员只能在用户操作节点变更。
- 工休比用于解释可持续性：`恢复效率 / (恢复效率 + 消耗效率)`。

来源：[Arknights Mower 排班教学](https://arkmowers.github.io/arknights-mower/manual/schedule/#_31)，获取日期 2026-07-29。公式和基础规则作为社区资料使用，最终以游戏内表现和可复现实测为准。

## 本仓库的保守实现

- 仅使用宿舍基础恢复率；宿管单回、群回和其他宿舍技能在结构化前按 0 计。
- 使用独立床位分配 MILP，在每个操作区间为下班干员分配固定宿舍。
- 要求每名工作干员的日恢复能力不低于实际日消耗，并迭代固定排班验证周期最低心情不低于 0。
- 导出的 `schedule.json` 必须包含每间宿舍的实际名单。

## 明确排除的自动化约定

以下内容属于 Mower 的执行接口或自动化策略，不进入本仓库模型：

- 主班、替班、Free 位、低优位等配置字段。
- 副表触发、用尽刷新、自动读取心情和自动换位。
- Mower 对宿管位置、书写顺序、锁定状态的要求。
- 任何设备控制、截图识别或自动操作脚本。

这些策略可作为人工排班设计启发，不能作为收益或心情闭环的验证依据。
