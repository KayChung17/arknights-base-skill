# 混合优化模型

## 分层结构

优化流程分为四层：

1. 单房间组合枚举。
2. 全局二元混合整数模型。
3. 多候选无好割搜索。
4. 同时基建范围复算。

枚举阶段处理复杂技能与房间内部组合，MILP 处理跨房间资源竞争、无人机库存和节点分配，复算阶段处理全局联动、无人机产出、资源成本和仓库封顶。

## 决策变量

对每个操作区间 `t`、房间 `r` 和候选组合 `c` 建立二元变量：

```text
x[t,r,c] = 1  该区间在该房间使用该组合
x[t,r,c] = 0  其他情况
```

对相邻区间使用同一组合的情况建立连续性变量：

```text
y[t,r,c] = x[t,r,c] AND x[t+1,r,c]
```

无人机使用、库存和溢出变量：

```text
d[t,r,p] = 节点t投入房间r收益档案p的无人机数量
I[t] = 节点t操作前无人机库存
w[t] = 区间t恢复后超过容量的无人机
```

## 硬约束

### 房间选择

每个房间、每个区间恰好选择一个候选组合。

### 同时进驻

同一干员在同一区间最多出现在一个房间。

### 每日工时

每名干员的区间工时总和不得超过 `max_daily_work_hours`。模型默认值为 24 小时，只承担可行性上限；实际长期排班需要在决策上下文中设置更严格的数值，或提供恢复事件。

### 无人机库存与分配

无人机基础恢复为每小时10架。每座已进驻发电站提供5%基础加成，干员充能技能与其相加。1架无人机减少3分钟基础时间。模型只允许在操作节点分配无人机，并要求分配目标对应当前选中的房间组合。

循环日库存满足：

```text
I[next] = I[current] - Σd + recovered - w
```

库存不得为负，不能超过容量，超出部分进入 `w`。无人机加速带来的赤金、碎片、合成玉、龙门币、经验、赤金消耗、碎片消耗、龙门币成本和固源岩成本全部进入模型。

### 资源平衡

搓玉目标默认启用源石碎片平衡约束：自然产量与无人机加速碎片产量不得低于自然订单及无人机加速订单的碎片消耗。可以通过 `resource_balance_safety_factor` 增加安全余量。

### 仓库容量

MILP 目标和资源平衡使用每个操作区间内的仓库封顶产量。复算阶段再次应用仓库限制，并报告全局加成导致的新溢出。

## 目标函数

模型对以下指标进行加权：

- 龙门币贸易工作量。
- 合成玉。
- 赤金。
- 作战记录经验。
- 人力联络。
- 控制中枢代理值。
- 无人机加速后的产出和资源成本。
- 固定订单价值。
- 相邻区间保持同一组合的连续性。

权重由大模型根据用户目标写入 `preferences.solver_weights`，或使用内置 `balanced`、`orundum`、`lmd`、`low_operation` 配置。

## 候选库截断

单房间完整组合数会快速增长。枚举器先按单人能力形成房间候选池，再完整枚举该池内组合，保留：

- `top_k` 个高分组合。
- 最多 `top_k` 个多样性组合。

多样性尾部降低相同核心干员反复出现在所有候选中的概率。只要任一房间发生候选池或组合截断，求解结果只能称为当前候选库中的最佳方案。

## 多候选与复算

`solve_schedule.py` 使用无好割排除已经返回的完整排班，并求解多个代理目标候选。每个候选随后由 `simulate_schedule.py` 复算：

- 同时工作干员构成的全局计数。
- 房间效率。
- 仓库封顶。
- 自然与无人机加速产生的碎片生产和消耗。
- 无人机节点库存、发电站恢复、分配与容量溢出。
- 工时与保守心情轨迹。

最终选择依据复算分数。由于代理目标与复算目标仍有差异，当前实现不证明复算目标的全局最优性。

## 最优性范围

`proxy_optimal_within_complete_candidate_library` 表示：

- 所有房间候选库完整。
- MILP 在声明的 gap 内完成。
- 结论只针对代理目标。

`best_found_within_truncated_candidate_library` 表示候选库发生截断。

`actual_simulation_global_optimality_proven` 当前固定为 `false`，直至所有特殊机制、随机订单路径、心情恢复和全局联动进入同一个优化目标。无人机已经进入MILP，但未知当前龙门币订单时仍使用期望值。
