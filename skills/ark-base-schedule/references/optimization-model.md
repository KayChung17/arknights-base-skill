# 混合优化模型

## 分层结构

优化流程分为四层：

1. 单房间组合枚举。
2. 全局二元混合整数模型。
3. 多候选无好割搜索。
4. 同时基建范围复算。

枚举阶段处理复杂技能与房间内部组合，MILP 处理跨房间资源竞争、无人机库存和节点分配，复算阶段处理全局联动、无人机产出、资源成本和仓库封顶。

## 决策变量

对每个操作区间 `t`、房间 `r` 和候选组合 `c` 建立二元变量：

```text
x[t,r,c] = 1  该区间在该房间使用该组合
x[t,r,c] = 0  其他情况
```

对相邻区间使用同一组合的情况建立连续性变量：

```text
y[t,r,c] = x[t,r,c] AND x[t+1,r,c]
```

无人机使用、库存和溢出变量：

```text
d[t,r,p] = 节点t投入房间r收益档案p的无人机数量
I[t] = 节点t操作前无人机库存
w[t] = 区间t恢复后超过容量的无人机
```

## 硬约束

### 房间选择

每个房间、每个区间恰好选择一个候选组合。

### 同时进驻

同一干员在同一区间最多出现在一个房间。

### 每日工时

每名干员的区间工时总和不得超过 `max_daily_work_hours`。模型默认值为 24 小时，只承担可行性上限；实际长期排班需要在决策上下文中设置更严格的数值，或提供恢复事件。

### 无人机库存与分配

无人机基础恢复为每小时10架。每座已进驻发电站提供5%基础加成，干员充能技能与其相加。1架无人机减少3分钟基础时间。模型只允许在操作节点分配无人机，并要求分配目标对应当前选中的房间组合。

循环日库存满足：

```text
I[next] = I[current] - Σd + recovered - w
```

库存不得为负，不能超过容量，超出部分进入 `w`。无人机加速带来的赤金、碎片、合成玉、龙门币、经验、赤金消耗、碎片消耗、龙门币成本和固源岩成本全部进入模型。

### 资源平衡

搓玉目标将源石碎片和赤金的日净变化 `0` 作为目标。`hard` 模式直接加入下界；`soft` 模式为目标约束加入非负短缺变量，并按 `shortfall_penalty` 扣减目标函数。`hard_minimum` 可在软模式下保留库存安全线。代理消费倍率默认取 `1.0`，额外安全余量必须由项目配置显式提供；最终模拟始终使用真实流量复核。

软模式允许候选进入效率排序，却不代表它能无限重复。模拟器根据 `base_state.inventory` 与 `horizon` 计算 `resource_sustainability`：无每日短缺时为 `sustainable_repeating_day`；存在短缺时为 `inventory_consuming_candidate`，并给出各资源每日消耗、可维持天数以及配置周期是否可行。`steady_state` 下任何短缺都不能标作长期可执行方案。

### 仓库容量

MILP 目标和资源平衡使用每个操作区间内的仓库封顶产量。复算阶段再次应用仓库限制，并报告全局加成导致的新溢出。

## 目标函数

模型对以下指标进行加权：

- 龙门币贸易工作量。
- 合成玉。
- 赤金。
- 作战记录经验。
- 人力联络。
- 控制中枢代理值。
- 无人机加速后的产出和资源成本。
- 固定订单价值。
- 相邻区间保持同一组合的连续性。

权重由大模型根据用户目标写入 `preferences.solver_weights`，或使用内置 `balanced`、`orundum`、`lmd`、`low_operation` 配置。

## 候选库截断

单房间完整组合数会快速增长。枚举器先按单人能力形成房间候选池，再完整枚举该池内组合，保留：

- `top_k` 个高分组合。
- 最多 `top_k` 个多样性组合。

多样性尾部降低相同核心干员反复出现在所有候选中的概率。只要任一房间发生候选池或组合截断，求解结果只能称为当前候选库中的最佳方案。

### 联动组合包

`assets/synergy-bundles.json` 保存已经核对公式的跨房间联动。候选池截断前保留组合包的必选干员、备选干员和分组成员；同一房间内能组成完整核心的组合优先进入多样性尾部。控制中枢、办公室、宿舍与生产房间成员分别保留，完整班次形成后再由模拟器计算跨房间收益。

攻略中只出现阵容或纸面数字、尚缺触发条件和公式的条目使用 `discovery_only`，不会改变候选库。只有 `verified_formula` 组合包参与候选保护。组合包提供搜索方向，不形成强制进驻约束。

## 多候选与复算

`solve_schedule.py` 使用无好割排除已经返回的完整排班，并求解多个代理目标候选。每个候选随后由 `simulate_schedule.py` 复算：

- 同时工作干员构成的全局计数。
- 已验证联动组合包对应的跨房间技能与中间产物。
- 房间效率。
- 仓库封顶。
- 自然与无人机加速产生的碎片生产和消耗。
- 无人机节点库存、发电站恢复、分配与容量溢出。
- 工时与保守心情轨迹。

最终选择依据复算分数。由于代理目标与复算目标仍有差异，当前实现不证明复算目标的全局最优性。

### 被覆盖技能的机会成本

候选组合记录特殊订单的生效与受抑制效果，以及巫恋等效率清零机制的逐人贡献。高价值效果被覆盖时，候选库额外保留同订单类型、逐项代理产出不下降的替代占位者。求解后执行两阶段邻域搜索：先用等收益组合释放受抑制干员，再尝试将其放入其他房间或班次。每一步都重跑完整日模拟并检查物理硬约束、用户硬底线、工时、宿舍和无人机闭环。该过程证明的是保留候选库内已检查邻域的支配关系，候选截断状态仍需单独报告。

## 最优性范围

`proxy_optimal_within_complete_candidate_library` 表示：

- 所有房间候选库完整。
- MILP 在声明的 gap 内完成。
- 结论只针对代理目标。

`best_found_within_truncated_candidate_library` 表示候选库发生截断。

`actual_simulation_global_optimality_proven` 当前固定为 `false`，直至所有特殊机制、随机订单路径、心情恢复和全局联动进入同一个优化目标。无人机已经进入MILP，但未知当前龙门币订单时仍使用期望值。
