# 无人机恢复与加速模型

## 已采用的确定机制

- 基础恢复速度为每 6 分钟 1 架无人机，即每小时 10 架。
- 每座已进驻干员的发电站提供基础 5% 充能加成；发电站干员技能提供的百分比与这些基础加成相加。
- 1 架无人机减少 3 分钟基础制造时间或基础订单时间。
- 无人机减少的是基础时间，制造生产力和贸易订单效率不会再次放大无人机带来的进度。
- 默认无人机容量为 235。超过容量的恢复量作为 `drone_waste` 记录。

区间 `t` 的恢复量为：

```text
recovered[t] = hours[t] × 10 × (1 + total_power_bonus_pct[t] / 100)
```

其中：

```text
total_power_bonus_pct[t]
  = Σ(每座已进驻发电站的 5% + 当前干员充能技能百分比)
```

## 每架无人机的确定产出

| 目标 | 基础时间 | 完成一个单位或订单需要的无人机 | 每架无人机对应产出或消耗 |
|---|---:|---:|---|
| 赤金 | 72 分钟/件 | 24 | 1/24 件赤金 |
| 源石碎片 | 60 分钟/件 | 20 | 0.05 件碎片，同时消耗 80 龙门币和 0.1 固源岩 |
| 中级作战记录 | 180 分钟/份 | 60 | 1/60 份，即约 16.667 经验 |
| 合成玉订单 | 120 分钟/单 | 40 | 0.5 合成玉，同时消耗 0.05 件源石碎片 |
| 可露希尔特别订单 | 144 分钟/单 | 48 | 25 龙门币，同时消耗 1/24 件赤金 |

普通龙门币订单由当前贸易站等级的订单分布计算期望值：

- 1 级：固定 2 赤金、1000 龙门币、144 分钟。
- 2 级：60% 为 2 赤金订单，40% 为 3 赤金订单。
- 3 级：30% 为 2 赤金订单，50% 为 3 赤金订单，20% 为 4 赤金订单。

但书、龙舌兰、可露希尔、U-Official 和佩佩的已验证订单规则会替换或修正普通期望模型。没有提供当前订单的剩余时间和类型时，模型使用上述期望值，并在结果中标记 `probabilistic`。

## 数学模型变量

在每个操作节点 `t`、可加速房间 `r` 和无人机收益档案 `p` 上建立非负整数变量：

```text
d[t,r,p] = 节点 t 投入该房间的无人机数量
```

同时建立库存和溢出变量：

```text
I[t] = 节点 t 操作前的无人机库存
w[t] = 区间 t 恢复后超过容量而损失的无人机
y[t,r] = 节点 t 是否选择房间 r 作为唯一无人机目标
```

循环日库存约束为：

```text
I[next(t)]
  = I[t]
  - Σ d[t,r,p]
  + recovered[t]
  - w[t]
```

并满足：

```text
0 ≤ I[t] ≤ capacity
0 ≤ Σ d[t,r,p] ≤ I[t]
Σ_r y[t,r] ≤ 1
d[t,r,p] ≤ capacity × y[t,r]
w[t] ≥ 0
```

若启用 `drone_repeating_day_balance`，最后一个区间连接回第一个节点，保证无人机库存可以按同一方案持续循环。非循环试算可关闭该选项并提供 `initial_drone_stock`。

## 分配规则

- 无人机只在用户声明的操作节点投入。
- 每个操作节点至多选择一个房间加速，与 `schedule.json` 的单一 `drones.room/index` 控件一致；该节点的无人机可以在这个房间内连续使用并立即收取。
- 默认每个操作节点用完当前可用无人机；连续恢复模型只允许留下小于 1 架的不可用舍入余量，即 `0 <= I[t] - sum(d[t,r,p]) < 1`。
- 分配变量必须与该节点实际选中的房间组合联动。
- 加速源石碎片会进入碎片产量、龙门币成本和固源岩成本。
- 加速合成玉订单会进入合成玉产量和碎片消耗。
- 加速龙门币订单会进入龙门币收益和赤金消耗。
- 无人机加速后的产物按节点内立即收取处理，因此不会占用到下一个上线节点的仓库容量。
- 发电站技能只增加恢复量，恢复量不再作为独立收益重复计分。

## 输出字段

`selected_solution` 记录：

- `drone_allocations`
- `drone_inventory`
- `drone_waste`

`simulation.drone_plan` 记录：

- 容量和循环日设置。
- 每个区间的起始库存、节点使用量、发电站总加成、恢复量、溢出量和结束库存。
- 每次分配减少的基础分钟数。
- 每架无人机和本次投入对应的产出、消耗与成本。
- `feasible` 库存闭环结果。

## 当前边界

- 普通龙门币订单在未知当前订单状态时使用等级分布期望值。
- 模型允许同一节点在选定房间内连续加速并立即收取；实际操作需要用户完成对应点击。
- 无人机容量可由用户覆盖。未提供时使用 235。
- 无人机分配已经进入 MILP 和资源平衡；随机订单的完整概率路径仍在复算层使用期望值。
