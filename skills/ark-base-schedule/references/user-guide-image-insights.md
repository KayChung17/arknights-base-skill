# 用户提供攻略图片的可用信息

来源：用户于 2026-07-29 提供的三张基建攻略图片。图片中的颜色、百分比和干员组合属于攻略作者的版本化经验，不能直接替代本地结构化技能数据。

## 可迁移的排班思想

- 小组：有技能联动的干员作为同一组，换班时整组进出，避免只替换其中一人导致组合失效。
- 大组：控制中枢干员与贸易站、制造站干员的全局组合需要同时评估；同组成员的同时上下班会改变全局加成。
- 动态换班：高效组中某名干员心情耗尽后，在可操作节点启用替班，延长其余高效干员的工作时间。用户只有三个上线节点时，只能在所选的三个操作时刻发生换班；图片中的任意时刻自动换班收益不能直接计入。
- 宿舍协同：宿管和高效组需要按工休比安排，宿舍优先恢复下一班需要上岗且心情最低的干员。
- 颜色图例：红色通常表示需要精英化，蓝色表示较低练度可用，黑色表示低练度可用；这只是攻略标注，最终资格仍由 roster 和结构化技能检查决定。
- 方括号或花括号：图片标注的“必须同时上班”或推荐组合应转为候选 bundle，不能拆成独立的单干员效率排序。

## 当前仓库的处理边界

- 本地求解器已经按实际设施范围、技能叠加、工时、宿舍床位和重复日心情复算。
- 图片中的具体效率百分比、颜色资格、主班/替班字段、副表和自动化动作暂不作为数值输入。
- 需要将图片组合纳入候选时，先逐名核对 roster、精英化、技能版本、`effect_key`、`stacking` 和组合前置条件，再进入组合库。
- 任何依赖中途自动读取心情或自动换位的方案，都标记为“需要额外上线节点”，不能用于当前三次上线设置。
