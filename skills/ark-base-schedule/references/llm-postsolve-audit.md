# 求解后大模型审阅

## 职责边界

求解器负责搜索，脚本负责事实、模拟和硬约束验证，大模型负责语义判断与纠正决策。大模型不得凭纸面效率直接改写排班，也不得把未复算的建议当作最终结果。

## 审阅输入

审阅前读取同一次运行生成的：

- `result.json`：当前解、逐区间模拟、房间指标和资源流
- `audit.json`：硬约束、技能覆盖、心情和机会成本证据
- `coverage.json`：技能数据覆盖与未结构化风险
- `summary.json`：候选库截断、求解状态和失败诊断
- 反事实候选：空位填充、单人替换、整组替换、跨房间交换、无人机目标切换

## 审阅顺序

1. 先检查硬错误：同班重复、右侧固定人员冲突、房间容量、无人机多目标、资源硬下限、心情闭环和特殊订单覆盖。
2. 再检查技能语义：同站条件、同名升级覆盖、不同名叠加、暖机重置、控制中枢授予效果和中间产物链。
3. 再检查机会成本：高价值干员是否被低价值技能覆盖，空座是否存在正收益候选，低效率占位是否阻挡更好的全局分配。
4. 对每个问题从反事实候选中选择动作：`accept`、`replace`、`swap`、`fill_empty_slot`、`keep_with_reason`。

## 纠正请求格式

```json
{
  "decision": "replace",
  "target": {"segment_id": "segment_1", "room_id": "factory_2"},
  "from_operators": ["A", "B"],
  "to_operators": ["C", "D"],
  "reason": "完整模拟显示经验产量提高，且未增加碎片短缺",
  "evidence_ids": ["counterfactual-17", "skill-effect-204"],
  "required_recheck": ["economy", "morale", "dormitory", "drones", "exclusivity"]
}
```

大模型可以提交多个有序请求。脚本逐个复算并返回 `accepted`、`rejected` 或 `blocked`；只有被接受的请求才进入下一轮审阅。最终审计记录同时保存原始方案、纠正请求、复算差值和未采纳理由。

## 常见审阅信号

- 生产/贸易房间有空座，存在完整模拟收益为正的空闲干员。
- 房间已有干员提供的技能被特殊订单或效率清零覆盖。
- 组合的局部纸面效率高，但占用了控制中枢、贸易站或制造站的核心联动成员。
- 空闲干员填入后只增加纸面效率，完整模拟显示心情、资源或无人机机会成本恶化。
- 纠正动作改变右侧名单、宿舍、产品或无人机目标后，旧验证全部失效，需要重新运行。
