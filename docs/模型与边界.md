# 模型、审计与边界

## 决策层次

1. 外层选择布局、建筑等级和产品分配。
2. 枚举每个房间的合法干员组合。
3. MILP 在每个操作区间选择一个组合，并处理同一时间干员互斥、每日工时、资源下限和无人机整数分配。
4. 模拟器使用所有同时工作干员复算全局联动、仓库、订单、无人机、经济和保守心情。
5. 审计器检查硬约束和最优性措辞。

## 已建模

- 建筑容量和电力预算。
- 已拥有干员与当前精英化、等级解锁。
- 同一时间重复进驻。
- 每日工时。
- 赤金、碎片、龙门币与合成玉资源流。
- 无人机恢复、容量、节点使用、溢出和重复日闭环。
- 制造站仓库封顶。
- 已结构化的特殊订单与全局联动。
- 候选库截断和求解 gap。

## 仍有限制

- 产品目前在一天内固定，未将操作节点切换配方作为外层决策。
- 宿舍床位、精确氛围、菲亚梅塔恢复和所有恢复链尚未全部进入 MILP。
- 普通订单在未知当前队列时采用期望分布。
- 部分复杂技能在求解后模拟，代理目标与最终模拟目标不完全一致。
- 内置干员技能数据不是全游戏完整库。

## 为什么需要审计

早期版本曾出现验证参数与公开运行参数不一致、无人机只记录恢复而未分配、建筑状态被攻略模板隐式覆盖等问题。1.0.0 将配置、输入哈希、运行环境、求解范围和硬约束审计写入输出，避免报告与实际运行脱节。
