# 输入门禁与运行验证

本版本把“先收集输入、再运行求解器、最后验证同次运行产物”落实到命令行和项目流程中。

## 标准流程

```bash
python arkbase.py preflight project.json --output preflight.json
python arkbase.py run project.json --output-dir output/my-project
python arkbase.py verify output/my-project
```

`run` 默认使用严格输入模式。关键字段缺失时返回退出码 4，并输出 `needs_input` 或 `conflict`，不会进入布局搜索、组合枚举和排班求解。

只有用户在配置中明确授权仓库默认值时，才使用：

```bash
python arkbase.py run project.json --allow-defaults
```

授权方式：

```json
{
  "input_policy": {
    "allow_repository_defaults": false,
    "authorized_defaults": [
      "/search/top_k",
      "/search/operator_pool_size",
      "/search/time_limit_seconds"
    ]
  }
}
```

`config.resolved.json` 的 `_resolution.source_map` 会记录每个关键值来自用户输入、旧字段迁移或用户明确授权的默认值。

## 预检状态

- `ready`：关键输入完整，可以进入求解器。
- `needs_input`：字段缺失，调用方应一次性询问缺失项。
- `conflict`：字段互相矛盾或文件不存在。
- `execution_blocked`：输入完整，但当前求解器尚未支持该运行语义。

当前版本只执行 `horizon.mode: steady_state`。`finite_days` 已纳入配置和库存字段检查，但会进入 `execution_blocked`，防止被静默当作重复日稳态。

## 验证产物

一次完整运行生成：

- `preflight.json`
- `result.json`
- `audit.json`
- `coverage.json`
- `pareto.json`
- `report.md`
- `config.resolved.json`
- `summary.json`
- `run-manifest.json`
- `verification.json`

`verify` 检查：

1. 文件是否完整；
2. `run_id` 和配置哈希是否一致；
3. 核心文件哈希是否与 `run-manifest.json` 一致；
4. 预检、审计和覆盖率是否通过发布门禁；
5. 结果是否包含求解器选中候选；
6. 报告和核心数值是否存在；
7. 可选的扩大候选库复算是否稳定。

启用稳定性复算：

```bash
python arkbase.py verify output/my-project --stability-check --expanded-factor 2
```

该命令把 `top_k`、`operator_pool_size` 和 `time_limit_seconds` 同时扩大，再运行一次完整求解，比较核心资源指标。

## 字段迁移

旧字段：

```json
"minimum_orundum_shard_balance": 0
```

新字段：

```json
"minimum_originium_shard_balance": 0
```

`Orundum` 对应合成玉，`Originium Shard` 对应源石碎片。旧字段暂时兼容，预检会生成弃用警告；新旧字段同时存在且数值不同会进入 `conflict`。
